01 / The approach

A compiler,
all the way through.

Mule parses Python itself, analyzes control flow and types, selects native representations, and emits LLVM IR. Functions and control flow become native code, not instructions for a Python evaluator.

Read the native lowering specification ↗

Built on compiler analysis

The architecture follows SBCL’s compiler, historically called Python: explicit intermediate representations, type analysis, local-call analysis, and representation selection.

No CPython runtime

Generated executables use Mule’s own native runtime. They do not link CPython or require a Python installation to run.

Work in progress

A limited subset, not a drop-in replacement. Mule is experimental. Python compatibility and standard-library coverage are incomplete. Start with small programs and consult the implemented subset and conformance results.

03 / Try it locally

From source
to executable.

Build from the repository. The mule command compiles your program, caches the executable, and runs it. The first invocation includes a native build.

Build prerequisites

Linux x86-64, Clang, Rust with its bundled LLVM LLD linker, the GMP shared library, free-threaded Python 3.15t, and uv.

Python and uv run the compiler. Generated executables do not need Python.

TerminalFrom a local checkout

Get the source

git clone https://github.com/justinvanwinkle/mule.git
cd mule
uv sync

Compile and run a small program

uv run mule -c 'print(40 + 2)'
42

Or build an executable explicitly

uv run python -m mule.compiler examples/factorial.py \
  -o build/factorial --emit-llvm build/factorial.ll
./build/factorial

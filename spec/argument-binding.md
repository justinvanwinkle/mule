# Function argument binding

Explicit `type.__call__` uses the shared compiled constructor to invoke
`__new__` and, for a returned instance of the requested class, `__init__`.
Calling that base implementation bypasses a custom metaclass call hook, while
ordinary class invocation still selects the hook. SBCL `src/pcl/ctor.lisp`,
`constructor-function-form`, `fallback-generator` and `fast-make-instance`,
similarly distinguishes custom construction from allocation/initialization
through the default constructor. Python requires `type.__call__` to remain
available to explicit and `super()` calls. The native adapter only packs
borrowed positional/keyword buffers and invokes the existing compiled entry;
it does not implement another constructor algorithm.

Status: implemented for the subset below.

## SBCL reference and required adaptations

SBCL `src/compiler/debug-dump.lisp`, `debug-info-for-component`, emits the
simple-fun name, argument list, source/documentation and type metadata from entry
information. Mule likewise emits immutable signature metadata from its Lambda
and Signature records beside the existing native code header. Code objects are
compiled Python objects cached per native code header, shared between closures
and traceback frames; Rust only stores header pointers and retained metadata/cache
values. Parameter counts, canonical `co_varnames` argument order, code flags,
cell/free names and initial captured positional/keyword defaults are available
to ordinary Python introspection. No bytecode object or evaluator is introduced.
Code replacement is unsupported. Public default replacement and keyword-default
mutation do not yet alter compiled binders; that existing gap requires mutable
signature/default analysis and invalidation of omitted-default direct-call proofs.

`src/compiler/locall.lisp:make-xep-lambda-expression` constructs external entries
for fixed and optional-dispatch functions. External entries select the applicable
arity and transfer control to an internal entry. `convert-more-call` verifies
constant keyword arguments and rearranges them for a direct main-entry call.
`src/compiler/ir2tran.lisp:init-xep-environment` arranges argument-count checking
and access to excess arguments. Mule retains separate external and internal
entries, borrowed argument views, and guarded direct calls to known bodies.

The generated external entry also binds keyword-free calls directly when all
unsupplied keyword-only parameters have defaults, including signatures with
`**kwargs`. It checks the positional count, fetches captured defaults, builds a
rest tuple only for `*args`, and creates a fresh empty keyword dictionary through
the same compiled `build_dict` protocol as a dictionary display. Allocation
failure releases an already-created rest tuple before returning the error.
Calls with supplied keywords or an unsuitable positional count retain the
general compiled binder. A `**kwargs` parameter alone does not permit excess
positional arguments.

The external entry outlines general keyword binding into a separate non-inlined
function. Positional calls therefore do not share its variable-sized scratch
storage. Keyword frequency is not assumed: the binder is not marked cold.
An ordinary borrowed `ArgumentView` selects an inlined physical entry once;
that entry reads the count and value buffer directly. Argument acquisition
clears a supplied ownership-mask bit to transfer a reference, or retains a
borrowed value when the bit is unset or the index exceeds the mask width.
Captured defaults still use the actual callable's default storage. Receiver
and keyword views retain their existing physical access paths.

This follows SBCL's `init-xep-environment` and `make-xep-lambda-expression`:
check the entry shape and count before moving arguments from known locations.
Mule's existing C-layout borrowed buffer replaces SBCL register/stack argument
locations. Rust layout tests verify the emitted offsets; no alternative binder
or new argument representation is introduced.

This follows the shape-specific external entries generated by SBCL's
`make-xep-lambda-expression` and argument arrangement in `convert-more-call`
(`src/compiler/locall.lisp`). Python additionally requires a distinct mutable
dictionary for every collected keyword argument set, even when it is empty;
that language-level construction remains compiled Python, not a Rust binder.

Local-call analysis starts collecting parameters with the container types the
entry guarantees: `*args` is an exact tuple with unknown length and element
types, and `**kwargs` is a dictionary with unknown contents. These are entry
facts, not permanent variable declarations; reassignment and control-flow joins
update them normally. SBCL's `convert-more-entry` in
`src/compiler/ir1tran-lambda.lisp` and the `%listify-rest-args` declaration in
`src/compiler/fndb.lisp` similarly expose the rest container's result type to
compiler analysis. Python collects positional rest arguments into a tuple and
keyword rest arguments into a dictionary rather than a Lisp list.

An annotation on a collecting parameter describes each collected value, not
the tuple or dictionary itself. The existing parameter-assertion prologue
iterates positional rest items and keyword rest values under the selected
safety policy. Keyword keys and the collecting container are not cast to the
annotated value type. This preserves the entry's tuple/dictionary facts instead
of falsely reporting a valid keyword-value annotation as a container-type
contradiction.

Python default expressions run once when the definition executes, whereas Lisp
optional defaults run on entry. Mule therefore evaluates defaults in source order
before publishing the function, stores owned references on that function, and
makes those values available through the external entry's borrowed argument
view. Repeated definitions can have identical code but different captured values;
optimization must use the actual callable's defaults, never a compile-time cache.

Python rejects a parameter supplied both positionally and by keyword and rejects
positional-only names used as keywords. Unlike Lisp's keyword handling, duplicate
binding is an error. Keyword-only parameters never consume positional arguments.
These binding rules are compiled Python generated for each signature; Rust only
provides borrowed argument-buffer access, ownership, callable invocation, and
physical allocation. Binding precedes body annotation checks. `None` is a valid
argument and default; missing values use a private identity sentinel.

Complete known calls can arrange arguments at compile time and enter the internal
body after checking callable identity. General calls enter a generated binder,
which binds owned local references and calls the internal body directly, just as
SBCL's generated external lambda calls its main entry. The binder retains the
actual defining namespace separately from its private exception namespace. It
transfers owned argument references to the body and cleans its own references on
success and failure; no intermediate normalized-argument tuple is allocated.
Keyword names and values remain in original evaluation order until binding.
All argument expressions execute before binding errors are raised.

Imported function metadata remains a guarded target prediction when a call's
result is unused or its inferred result is `None`. Constraint propagation keeps
that prediction on the callee reference without marking the binding proven.
The matching path can enter the known body directly; a rebound callable retains
the existing dynamic fallback and actual namespace, capture, and default state.
This follows SBCL's local-call target and argument propagation while adapting
Python's mutable imported bindings through an identity guard. An importing
unit may use the definition's metadata and result derivation, but only the
defining unit owns and specializes its function's entry contexts.

Resolved method calls predict compiled method bodies for both receiver shapes.
A bound call supplies its receiver separately; an explicit class access such as
`property.__set__(descriptor, instance, value)` supplies every parameter in the
argument list. Attribute and descriptor resolution still runs first. The
generated helper selects the receiver shape once, then checks the resulting
callable's actual entry against only candidates that accept that shape, retaining
their original order. A shape with no eligible candidates enters the general
path without checking entries. The matched body receives that callable's actual
namespace, captures and defaults. Missing captured defaults,
an unsuitable argument shape or another callable entry retain the general call
path. Parameters transfer ownership once, whether the receiver was separate or
an explicit argument; frame rejection releases the original owned operands.

SBCL `src/compiler/locall.lisp`, `make-xep-lambda-expression` and
`convert-more-call`, similarly arrange known argument shapes for a main entry
while preserving external entry checking for other calls. Python's additional
adaptation is the receiver selected by descriptor lookup: class access must not
insert another implicit receiver. This optimization does not establish a class
layout or bypass user descriptors, metaclass calls or initializer protocols.

Keyword constructor calls use a compiled Python allocation/initialization
protocol, backed by physical instance allocation and forwarding of the borrowed
argument view. Existing positional native constructor callbacks retain their
fast path for complete fixed signatures. Optional or variadic constructors must
use the general binding path rather than incorrectly applying a fixed count.

Binding covers defaults, explicit keyword calls, positional-only and keyword-only
parameters, positional rest parameters, and `**kwargs` collection. The external
entry accepts the borrowed argument view after call-site expansion; expansion
itself is a separate sequence/mapping operation.

## Implemented boundaries and checks

Generated binders support fixed positional-only, positional-or-keyword, required
and optional keyword-only, positional rest, and keyword rest parameters. Both
positional and keyword defaults are captured on each function object. Failed
default evaluation does not publish a replacement definition. Captured values are owned and released
with the function, including partial-definition failure and repeated definitions.
Unknown names, duplicate binding, too many positional arguments, and missing
required parameters raise catchable TypeError before the function body executes.
Messages identify binding failures but do not yet reproduce every CPython error
message, including grouped missing names and positional-only error precedence.

Calls to compiled user functions and methods accept explicit keywords, including
saved bound methods, imported functions, callable instances and inherited methods.
Constructor forwarding supports both boxed and native class layouts. Builtins
implemented through older positional native entries reject keyword calls rather
than silently ignoring them; keyword-capable builtin signatures remain work.
Function introspection attributes and mutation of __defaults__/__kwdefaults__ are
not implemented. The defaults context is function storage, not a user-visible
attribute or a type tag.

Known keyword calls are rearranged after source-order argument evaluation and
before the internal body. Missing optional arguments are fetched from the actual
callable only on the identity-guarded branch. Those calls avoid the normalized
argument tuple. Direct calls with omitted defaults currently use the unspecialized
internal entry rather than inferring specialized ranges from captured values.
Calls that do not fit the generated positional entry use the compiled binder
and directly invoke the internal body. Positional rest parameters receive a tuple;
keyword rest parameters receive a fresh dictionary, including for keyword-free
calls. General binding happens before annotation checks in the body; statically
known annotation contradictions in defaults and proven keyword calls also produce compile errors.

Tests cover source evaluation order, mutable captured defaults, None defaults,
repeated definitions, binding errors, positional rest tuples, imported functions,
methods and constructors, native layouts, inheritance, annotation safety and
error cleanup. A 1,000-iteration Valgrind probe through saved methods, captured
mutable defaults, duplicate arguments, and failed default evaluation reports no
memory errors or lost allocations (the platform stdout buffer remains reachable).

## Native validation

The full regression run completed with 1,540 passed and 590 expected failures.
After tightening implicit-receiver binding for keyword-only first parameters,
the final argument-binding suite completed with 24 passing cases. Ruff checks
and formatting checks pass. Corpus coverage increased from 11 to 13 native
programs; upstream stdlib execution remains one passing suite out of 557 attempted
(two suites execute, with seven individual tests attempted).

The `build/argument-call-benchmark.py` probe performs 20 million calls to
`add(value: mule.int64, *, step: mule.int64 = 3) -> mule.int64`, supplying `value`
by keyword and omitting `step`. It prints 60,000,000. Three process wall times
were 0.2971, 0.2901 and 0.2889 seconds for Mule and 0.6281, 0.6343 and 0.6309
seconds for standard Python 3.14.7 using the same source and annotation markers.
LLVM and Rust use optimization level 3 with full cross-language LTO. Machine
code in `build/argument-call-benchmark-loop.asm` retains the counted loop and
calls the internal add entry; the work is not folded into a constant result.
The direct branch reads the captured default from the guarded function object.
Global lookup, identity guards, ownership and numeric entry guards remain costs;
this measurement does not establish equivalent performance for arbitrary dynamic
calls, which execute the generated binder.
